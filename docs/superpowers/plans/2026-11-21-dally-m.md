# Community Dally M Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tippers cast secret 3-2-1 votes for the best players of each regular-season round; votes are revealed at close and add up to a season leaderboard on a new `/dally-m` page.

**Architecture:** The pipeline publishes `round_players` (who played each round) beside the players tables. Votes live in `dally_m_votes`, guarded by row-level security like `tips`; SQL functions define the voting window and views give the round results and leaderboard. The page reads candidates and the window through `siteDb` (public data) and votes through the viewer's Supabase session (RLS), with a sample module for local viewing.

**Tech Stack:** Postgres/Supabase SQL (PGlite in tests), Python 3.12 pandas pipeline, Next.js 15 / React 19 / Tailwind 4, vitest, pytest.

**Spec:** `docs/superpowers/specs/2026-11-21-dally-m-design.md`

## Global Constraints

- Regular season only (`matches.is_final` false); candidates are players with minutes > 0.
- Votes 3, 2, 1 to three different players; one set per tipper per round; the Model can't vote.
- Window: opens when the round has `round_players` rows; closes at the earliest kickoff after the round's last game (any round of the season, finals included); fallback last kickoff + 7 days.
- No one reads another tipper's votes before close, through any table, view or function; `analyst` gets nothing about votes.
- Leaderboard: closed rounds only; rank by total, then 3s, then 2s; equal on all three share a rank.
- Photos are nrl.com links only (`PlayerPhoto`, no next/image).
- Main menu: Round, Tips, Ladder, Dally M, More; Elo first in More.
- Follows DESIGN.md; impeccable detector clean; checked at 390, 768, 1440.
- Node isn't on PATH: `export PATH="/c/Program Files/nodejs:$PATH"`; Python is `.venv/Scripts/python`.

## Review Focus

1. A tipper re-saving a ballot that swaps two players between 3 and 2 must not trip the unique constraint (save the whole ballot in one statement after deleting the round's old rows, or upsert by `votes` with deferrable uniqueness) — Task 1 test `swaps two players between vote slots`.
2. A signed-out visitor on `/dally-m` sees the leaderboard prompt, not an error (votes are authenticated-only) — Task 5 handles `sb` null / no user.
3. A round with a postponed game that is played after the next round starts: its players join `round_players` but the round may already be closed — no crash, they're just not voteable — Task 1 test `closed round refuses new votes even with new players`.
4. Before the migration is applied the page must show a "coming soon" message, not a 500 — Task 4 `dallyMSource` returns `missing` on query failure.
5. Off-season (no open round, no rounds this season yet) the page still renders the last season's leaderboard — Task 4 picks the newest season in `round_players`.
